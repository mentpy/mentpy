    Simulating MBQC Circuits¶

    In the previous tutorial, you have learned how to create an MBQC circuit using the MBQCircuit class. Now, we will use this circuit to run an actual experiment. We will use the PatternSimulator class to create a simulator. Let’s try it out

    In [1]: grid_cluster = mp.templates.grid_cluster(3, 5)

In [2]: simulator = mp.PatternSimulator(grid_cluster)

In [3]: print(simulator)
PatternSimulator (RustSimulator for MBQCircuit with 15 qubits.)

    The default backend="rust" supports native tensor contraction, sampled trajectories, and gradients of postselected patterns, including XY, XZ, YZ, XYZ and Pauli measurements. backend="numpy" is a reference implementation. backend="jax-tn" remains available for code using JAX transformations.

    For larger forced-outcome patterns, the jax-tn backend contracts the MBQC graph as a tensor network with JAX arrays. This backend supports JAX autodiff and can run on GPU when JAX is installed with CUDA support. It is most useful when the measured resource graph has low treewidth or when the output boundary is small enough to materialize.

    In [4]: tn_simulator = mp.PatternSimulator(grid_cluster, backend='jax-tn')

In [5]: output_state = tn_simulator(np.random.rand(len(grid_cluster.trainable_nodes)))

In [6]: print(output_state.shape)
(8, 8)

    Running the circuit¶

    Pass the measurement angles in trainable_nodes order. The simulator returns a density matrix by default. Pass output_form="sv" for the statevector of the selected branch. If the measurement angle of a node is fixed (i.e. the measurement object Ment is not trainable), you will not need to specify the measurement angle in the call to the simulator.

    In [7]: num_angles = len(grid_cluster.trainable_nodes)

In [8]: output_state = simulator(np.random.rand(num_angles))

In [9]: print(output_state.shape)
(8, 8)

    Different inputs¶

    If you want to run the circuit with a particular input state, you can specify it with the keyword argument input_state.

    In [10]: random_state = mp.utils.generate_haar_random_states(3)

In [11]: simulator.reset(input_state = random_state)

In [12]: output_state = simulator(np.zeros(num_angles))

In [13]: print(output_state.shape)
(8, 8)

    Observable costs¶

    The Rust tensor-network backend can evaluate Pauli-sum observables directly, which is useful for variational algorithms.

    In [14]: wire = mp.templates.linear_cluster(5)

In [15]: observable = mp.Observable({"Z": 1.0})

In [16]: simulator = mp.PatternSimulator(wire, backend='rust')

In [17]: value, gradient = simulator.expectation_and_grad(
   ....:     np.zeros(len(wire.trainable_nodes)),
   ....:     observable,
   ....: )
   ....: 

In [18]: print(value)
0.0

    Exact autodiff is the default when shots=None. To emulate finite measurement statistics while keeping the MBQC state preparation exact, pass a shot count to the same observable API:

    In [19]: exact_value = simulator.expectation(
   ....:     np.zeros(len(wire.trainable_nodes)),
   ....:     observable,
   ....: )
   ....: 

In [20]: shot_value = simulator.expectation(
   ....:     np.zeros(len(wire.trainable_nodes)),
   ....:     observable,
   ....:     shots=200,
   ....:     seed=7,
   ....: )
   ....: 

In [21]: print(exact_value, shot_value)
0.0 0.040000000000000036

    Use expectation_and_grad for exact observable objectives. For finite-shot objectives, differentiate a cost function with mp.gradients.get_gradient(cost, angles, method="parameter-shift") instead. See Molecular energies with an MBQC ansatz for an ansatz, a molecular Hamiltonian, and an explicit optimization loop.

    The Rust backend differentiates the normalized branch, so it includes changes in postselection probability. Parameters follow trainable_nodes order; XYZ measurements use a pair of angles and return a pair of derivatives. With force0=True, sample draws output shots from the selected branch. With force0=False, the Rust backend uses a lazy statevector trajectory and resamples intermediate measurements for every output shot, applying available flow corrections. Exact expectations in this mode describe one sampled branch, not an ensemble average. Native gradients require force0=True. The JAX compatibility backend only supports postselected tensor contraction.

    Native contractions represent default plus-state inputs implicitly and split high-degree copy tensors into rank-three factors. max_elements limits the size of an individual planned tensor; it is not a bound on total memory used by the gradient tape. Returning a statevector still requires exponential memory in the number of quantum outputs.

    Pauli propagation¶

    When you need an expectation rather than the entire output state, use backend="pauli" for causal-flow patterns with X, Y or XY measurements. The backend follows the flow paths to obtain logical rotations and CZ gates, then propagates the observable backward as a sparse Pauli sum. Propagation and reverse-mode gradients run in Rust; packed Pauli words and Clifford operations come from PPVM. These features are included in the standard installation.

    In [22]: pattern = mp.templates.grid_cluster(2, 4)

In [23]: simulator = mp.PatternSimulator(pattern, backend="pauli")

In [24]: angles = np.full(len(pattern.trainable_nodes), 0.3)

In [25]: observable = mp.Observable({"ZZ": 0.7, "XY": -0.2})

In [26]: value, gradient = simulator.expectation_and_grad(angles, observable)

In [27]: print(value, gradient.shape)
0.057388000531527816 (6,)

    This avoids an exponential output-state allocation and is useful for wide patterns whose observables remain sparse. Non-Clifford rotations can still produce exponentially many terms. max_terms limits the expansion and max_tape limits gradient storage; exceeding either raises an error without truncating the result. peak_terms reports the largest expansion of the last call. Gradients preserve terms whose value is zero but whose derivative is nonzero, including at Clifford angles.

    The current implementation supports up to 1024 logical wires, unmeasured outputs, and arbitrary normalized input vectors in input-node order. Default plus inputs and additional plus-state path roots stay implicit. Patterns with only generalized flow or Pauli flow are not yet supported by this backend. There is no approximate truncation mode yet.

    With force0=False, exact expectations describe a sampled corrected trajectory. Finite-shot expectations sample the Pauli eigenvalue and resample adaptive trajectories for each shot. Their distribution agrees with state simulation; the same seed need not produce the same bit sequence across different algorithms. Native gradients require force0=True.

    run, probabilities and joint sample calls use the Rust state simulator, with its usual output-memory costs. Use expectation or expectation_and_grad to obtain the sparse-propagation benefits. Run python -m benchmarks.pauli to compare the two algorithms on your machine.

    On Linux with an NVIDIA GPU, select device="cuda:0" to use cuPauliProp through MentPy’s native Rust interface. The standard Linux installation includes cuPauliProp and the CUDA runtime; a compatible CUDA 13 driver is required. A CUDA toolkit and a separate MentPy extra are not needed. CPU installations do not load these libraries or initialize a GPU.

    simulator = mp.PatternSimulator(pattern, backend="pauli", device="cuda:0")
value, gradient = simulator.expectation_and_grad(angles, observable)

    GPU expectations and reverse-mode differentiation preserve the same branch and ordering conventions. Default plus-state readout stays on GPU. For an explicit entangled input vector, its final Pauli expectations are computed in Rust on CPU using the supplied vector, and their cotangents seed GPU backpropagation. This avoids expanding the input into a density operator. State/probability/joint-shot methods still use the CPU Rust state simulator.

    max_memory limits MentPy’s owned GPU buffers, including the saved expansions and workspace. It excludes the CUDA context, library internals and host metadata. The default is 256 MiB. Exceeding this limit or max_terms raises an error; the calculation does not silently truncate or switch devices. CPU gradients use max_tape instead. CUDA_VISIBLE_DEVICES is respected.

    GPU launch and allocation costs dominate small patterns. Use python -m benchmarks.cupauli --device cuda:0 to measure first-call latency, warm runtime, and term growth against CPU propagation. The benchmark checks expectations and derivatives before reporting timings.

    Clifford+T rotations on a long wire¶

    The jax-tn backend is especially useful for one-dimensional clusters. A long 1D cluster can represent a compiled single-qubit rotation using only discrete XY-plane measurement bases. In the standard one-way convention, an XY measurement at angle alpha implements a J(alpha) step, so Clifford+T circuits can be lowered to a chain whose fixed measurement angles are only 0, pi/2, and pi/4.

    The optional pygridsynth package can synthesize a near-T Z-rotation into Clifford+T gates. The fallback string below is the sequence returned for this example with tolerance 1e-4. Install it with pip install "mentpy[synthesis]" when you want to compile new angles. The compiler is asked for -target_theta because the positive measurement pairs below implement the adjoint S and T phases in this forced-outcome convention.

    In [28]: target_theta = np.pi / 4 + 1e-3

In [29]: epsilon = "1e-4"

In [30]: fallback_gates = (
   ....:     "HTHTSHTSHTHTSHTHTHTSHTSHTSHTSHTHTHTSHTSHTHTSHTHTHTHTHTHTHT"
   ....:     "SHTHTHTSHTHTSHTHTSHTSHTSHTHTSHTSHTSHTSHTHTHTSHTSHTHTSHWWWWW"
   ....: )
   ....: 

In [31]: try:
   ....:     import mpmath
   ....:     from pygridsynth.gridsynth import gridsynth_gates
   ....:     gates = gridsynth_gates(
   ....:         theta=-(mpmath.mp.pi / 4 + mpmath.mpf("0.001")),
   ....:         epsilon=mpmath.mpf(epsilon),
   ....:     )
   ....: except ImportError:
   ....:     gates = fallback_gates
   ....: 

In [32]: def clifford_t_to_1d_angles(gates):
   ....:     angles = []
   ....:     for gate in gates:
   ....:         if gate == "H":
   ....:             angles.append(0.0)
   ....:         elif gate == "S":
   ....:             angles.extend([np.pi / 2, 0.0])
   ....:         elif gate == "T":
   ....:             angles.extend([np.pi / 4, 0.0])
   ....:         elif gate == "X":
   ....:             angles.extend([0.0, np.pi / 2, 0.0, np.pi / 2, 0.0, 0.0])
   ....:         elif gate == "W":
   ....:             pass
   ....:         else:
   ....:             raise ValueError(f"Unsupported gate {gate!r}")
   ....:     return np.array(angles)
   ....: 

In [33]: angles = clifford_t_to_1d_angles(gates)

In [34]: wire = mp.templates.linear_cluster(len(angles) + 1)

In [35]: for node, angle in zip(wire.outputc, angles):
   ....:     wire[node] = mp.Ment(angle, "XY")
   ....: 

In [36]: print(f"Clifford+T gates: {len(gates)}")
Clifford+T gates: 117

In [37]: print(f"T gates: {gates.count('T')}")
T gates: 44

In [38]: print(f"1D cluster nodes: {wire.graph.number_of_nodes()}")
1D cluster nodes: 180

In [39]: print(sorted({round(float(angle / np.pi), 2) for angle in angles}))
[0.0, 0.25, 0.5]

    The circuit above has no trainable angles. It is a fixed, long measurement pattern whose bases are only X, Y, and (X+Y)/sqrt(2). We can verify the effective one-qubit unitary by simulating the two computational-basis inputs with the tensor-network backend:

    In [40]: def simulated_unitary(circuit):
   ....:     columns = []
   ....:     for state in [np.array([1.0, 0.0]), np.array([0.0, 1.0])]:
   ....:         output = mp.PatternSimulator(
   ....:             circuit,
   ....:             input_state=state,
   ....:             backend="jax-tn",
   ....:         ).run([], output_form="sv")
   ....:         columns.append(np.asarray(output))
   ....:     return np.column_stack(columns)
   ....: 

In [41]: def rz(theta):
   ....:     return np.diag([np.exp(-0.5j * theta), np.exp(0.5j * theta)])
   ....: 

In [42]: def operator_error_up_to_phase(actual, target):
   ....:     phase = np.vdot(actual, target)
   ....:     phase = phase / abs(phase)
   ....:     return np.linalg.norm(phase * actual - target, ord=2)
   ....: 

In [43]: unitary = simulated_unitary(wire)

In [44]: error = operator_error_up_to_phase(unitary, rz(target_theta))

In [45]: print(error)
4.975174462476754e-05

    Scaling a one-dimensional tensor-network contraction¶

    The tensor-network backend does not build the full 2**n statevector for all measured qubits. In a one-dimensional cluster with one input and one output, the output state is still a single-qubit object even if the measured wire is long. That is the kind of low-treewidth pattern where jax-tn can go far beyond a dense statevector simulator.

    This executed example keeps the docs build small while still using the same code path as the long compiled rotation above:

    In [46]: large_n = 101

In [47]: large_wire = mp.templates.linear_cluster(large_n)

In [48]: fixed_angles = np.resize(
   ....:     [0.0, np.pi / 4, 0.0, np.pi / 2],
   ....:     len(large_wire.outputc),
   ....: )
   ....: 

In [49]: for node, angle in zip(large_wire.outputc, fixed_angles):
   ....:     large_wire[node] = mp.Ment(float(angle), "XY")
   ....: 

In [50]: large_simulator = mp.PatternSimulator(
   ....:     large_wire,
   ....:     backend="jax-tn",
   ....:     output_form="sv",
   ....: )
   ....: 

In [51]: large_state = large_simulator.run([])

In [52]: print(large_wire.graph.number_of_nodes())
101

In [53]: print(large_state.shape)
(2,)

In [54]: print(np.linalg.norm(np.asarray(large_state)))
0.9999999999999999

    For a local benchmark, increase n_nodes in the same pattern. The following block is intentionally not executed during the docs build:

    import time
import numpy as np
import mentpy as mp

n_nodes = 10_001
wire = mp.templates.linear_cluster(n_nodes)
angles = np.resize([0.0, np.pi / 4, 0.0, np.pi / 2], len(wire.outputc))
for node, angle in zip(wire.outputc, angles):
    wire[node] = mp.Ment(float(angle), "XY")

simulator = mp.PatternSimulator(wire, backend="jax-tn", output_form="sv")
start = time.perf_counter()
state = simulator.run([])
elapsed = time.perf_counter() - start

print(f"nodes: {wire.graph.number_of_nodes()}")
print(f"output shape: {state.shape}")
print(f"time: {elapsed:.3f}s")

    For high-output patterns such as a full 100-qubit GHZ state, the output representation itself is the limiting object: a dense statevector has 2**100 amplitudes. Use jax-tn for large measured resources with compact outputs or observable costs, and keep dense output states small.

    Output probabilities and shots¶

    probabilities returns exact output probabilities. sample returns a Samples object with output bitstrings, counts, shot count, measurement basis, and empirical frequencies. Output columns follow quantum_output_nodes.

    In [55]: wire = mp.templates.linear_cluster(5)

In [56]: sample_sim = mp.PatternSimulator(wire, backend="jax-tn")

In [57]: angles = np.zeros(len(wire.trainable_nodes))

In [58]: sample_sim.probabilities(angles)
Out[58]: Array([0.5, 0.5], dtype=float64)

In [59]: samples = sample_sim.sample(angles, shots=1024, seed=7)

In [60]: samples.counts
Out[60]: {'0': 517, '1': 507}

In [61]: x_samples = sample_sim.sample(angles, shots=1024, basis="X", seed=7)

In [62]: x_samples.expectation
Out[62]: 1.0

    Measurement branches¶

    Both backends default to force0=True, which selects outcome zero at every intermediate measurement. A zero-probability branch raises an error. JAX raises a runtime error when compiled execution reaches an impossible branch. MentPy uses the precision configured by the application. Set JAX_ENABLE_X64=1 before starting Python when the calculation needs double precision.

    Use backend="numpy", force0=False to sample intermediate outcomes. The simulator applies the pattern’s available flow corrections and evaluates controlled measurements against the recorded outcomes. Each run() returns a single trajectory and exposes its outcomes in sim.outcomes. probabilities() and exact expectation() refer to the state of that trajectory. sample() and expectation(..., shots=...) draw an independent trajectory for each shot in this mode.

    The legacy backend names numpy-sv, numpy-dm, trajectory, and pennylane select the unified NumPy simulator. Use Importing and Exporting Circuits for native PennyLane execution or other framework exports.
